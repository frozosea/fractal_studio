# AI 辅助分形探索经验与工作流

最后更新：2026-07-30

## 1. 文档目的

这份文档用于指导后续 AI agent 辅助用户探索、筛选并发布分形作品。当前目标是沉淀已经验证过的工作方法，**不是立即开发新的 agent、编排框架或自动化基础设施**。

规划中的四项核心能力是：

1. **找位置**：根据视觉意图寻找值得观察的坐标、尺度、特殊点和公式区域。
2. **调色**：在结构正确的前提下，用有限的、有目的的配色变体强化主题和层次。
3. **微调与构图**：围绕候选位置微调中心、尺度、旋转和画幅，形成可发布的构图。
4. **写文案并上架**：基于真实配方和最终图像生成标题、说明、标签与商品草稿，通过质量门后再发布。

AI 的定位应是“探索副驾驶”：擅长扩大搜索范围、记录参数、批量比较和排除明显失败；用户负责最终的审美判断、品牌判断与发布确认。除非用户明确授权，agent 不应把“生成成功”理解为“允许公开上架”。

## 2. 总体原则

### 2.1 图像是最终证据

数学属性只能缩小搜索范围，不能代替视觉验收。周期为 5、具有五重对称或位于某个特殊点附近，都不等于画面中必然出现清晰、分离的五角星；四重卫星结构也不等于自然形成符合预期的卍形。

因此，每个候选都必须经历：参数推导、低成本预览、视觉检查和结果记录。搜索器返回的是候选，渲染图才是判断依据。

### 2.2 一次只改变一类变量

位置、尺度、旋转、计算模式和配色同时变化时，无法判断改进来自哪里，也难以复现。推荐顺序是：

```text
结构位置 -> 观察尺度 -> 构图 -> 数值/染色模式 -> 调色板 -> 发布文案
```

用户只要求重新染色时，应保留坐标、尺度和公式；用户只要求构图微调时，不应顺手更换公式或目标结构。

### 2.3 精确配方与图像同等重要

每张候选图都要保存可复现的 canonical spec，而不能只保存 PNG。深度缩放必须保留 `centerReStr`、`centerImStr` 等完整精度字符串；double 形式的坐标只适合显示或浅层预览。特殊点、高精度与 perturbation 路径的具体约定见 [Special Points / 特殊点链路](special_points.md) 和 [Render Pipeline / 二维渲染链路](render_pipeline.md)。

### 2.4 少量、有解释的候选优于盲目堆图

一轮建议提供 3–8 个有明显区别的候选，并给出变化轴和推荐理由。agent 应先过滤明显空白、失焦、结构错误、过曝或缩略图不可读的结果，不应把几十张未经筛选的图片交给用户。

### 2.5 草稿、私有作品与已发布商品必须分离

探索结果默认保持私有或草稿状态。错误候选、过渡产物和被否决的标题不得留在市场中。配方、渲染资产、作品记录、listing 和发布状态是不同对象；自动化操作要逐项核对，且使用幂等键避免重复创建或重复上架。

## 3. 标准探索流程

```text
视觉意图
  -> 提取硬约束与软偏好
  -> 粗搜索位置和数量级
  -> 生成带索引的预览矩阵
  -> 筛选结构候选
  -> 调色矩阵
  -> 构图微调
  -> 高分辨率私有渲染
  -> 质量检查
  -> 文案与 listing 草稿
  -> 用户确认
  -> 发布并回查市场展示
```

推荐的单轮规模：

- 粗搜索 8–24 个低成本候选；
- 收敛到 3–6 个结构候选；
- 对最佳结构生成 4–8 个配色方案；
- 对最佳配色生成 3–9 个构图微调；
- 最终只高分辨率渲染 1–3 个版本。

这些数字是经验默认值，不是硬限制。目标明确时可以缩减；探索全新公式或 transition 区域时可以分批扩大，但每轮都要记录结论。

## 4. 功能一：帮忙找位置

### 4.1 先把自然语言转成约束

agent 开始搜索前，应将描述拆成两类：

- **硬约束**：公式族、Mandelbrot 或 Julia、是否要求 Mandelbrot 内嵌 Julia、主体数量、主体是否分离、主体必须位于小 Mandelbrot 周围、目标画幅等。
- **软偏好**：像山脉、深海、金属、红底黄星、画面疏密、中心或偏心构图等。

例如，“很多互不相连的五角星，红底黄星，而且希望在 Mandelbrot 里的 Julia 区域寻找”至少包含三项不可互换的硬约束：五角星轮廓、视觉上分离、Mandelbrot 内嵌 Julia。找到五重花瓣、五向辐射或直接 Julia 都不能标记为成功。

### 4.2 使用由粗到细的搜索金字塔

1. 从已知锚点、特殊点、mini-Mandelbrot 或用户给出的近似坐标开始。
2. 在对数尺度上扫视野，而不是只做线性微调。
3. 在每个尺度周围做小范围中心网格或低差异采样。
4. 只对视觉上接近目标的区域提高迭代数和精度。
5. 给每张预览附上候选 ID，保持图片与参数一一对应。

特殊点搜索时要检查 `accepted`、`actual.period`、residual 和 primitive/satellite 关系，不能只看 Newton 是否 `converged`。若目标是某个父周期之外的嵌套结构，还应排除仅仅落回父周期倍数的候选。

### 4.3 深缩放的尺度经验

深层 mini-Mandelbrot 的 nucleus 或 component 尺寸通常不是完整视觉结构的观察尺度。过度贴近 nucleus 容易只看到局部丝状物；拉远若干数量级后，才可能看出一圈 satellite 或内嵌 Julia 的整体组织。

实践中可以把“约几十倍 component 尺寸观察中心结构、约上千倍观察更完整邻域”作为起始启发式，但不能当公式使用。不同周期和区域差异很大，必须做对数尺度 sweep，并以预览判断。

深 zoom 中要从搜索到渲染全程传递精确十进制字符串，并选择 fp128/MPFR/perturbation 等可用高精度路径；否则坐标在进入渲染器前就可能被 double 舍入到错误位置。

### 4.4 位置助手的理想输出

每次返回一个经过排序的候选表：

| 字段 | 含义 |
|---|---|
| `candidateId` | 本轮稳定编号，与预览图一致。 |
| `centerReStr` / `centerImStr` | 可复现的精确中心。 |
| `scale` | 视野尺度及其含义。 |
| `source` | 已知锚点、特殊点求解、网格扫描或人工种子。 |
| `mathEvidence` | 周期、前周期、残差、兼容公式等数学依据。 |
| `visualObservation` | 实际看到的主体数量、连通性和构图。 |
| `constraintMatch` | 满足和未满足哪些用户约束。 |
| `nextAction` | 淘汰、继续缩放、平移或进入调色。 |

不要用数学证据替代 `visualObservation`，也不要为接近但不符合的形状起一个误导性标题。

## 5. 功能二：帮忙调色

### 5.1 先确认结构，再调色

调色可以突出层次、隐藏噪声或改变氛围，但无法把七向辐射变成五角星，也无法让错误坐标变成正确构图。结构未通过时，应返回位置搜索，而不是继续用色彩掩盖问题。

建议先用灰度、中性或结构清晰的内置 palette 检查几何，然后再构造少量命名清楚的配色方案，例如“朱红—金黄低频”“深蓝—金色高对比”“地形图层级色”。

### 5.2 分开控制染色变量

建议按以下顺序调整：

1. 数值 field / metric 与 `smooth`；
2. `colorMode`；
3. palette 或 `colorProgram` stops；
4. `cyclesPerOctave` 或 `cycles`；
5. `phase`；
6. interior / invalid color。

`eq_full` 搭配内置 palette 通常适合先观察全局层次。深缩放中，较低的 `cyclesPerOctave` 往往能形成更平静、连续的宽色带；`0.025–0.12` 可作为试探区间，但不是统一答案。

自定义 `colorProgram` v1 当前只支持 `colorMode=direct`，不能假定它能复刻 equalized 模式。自定义色带的输入语义、范围和限制以 [Coloring Contract / 染色合同](coloring_contract.md) 为准。遇到画面全灰、色带挤在一端或颜色完全不出现时，应该检查原始 field 分布或做参数 sweep，不能凭感觉反复猜 stop 阈值。

### 5.3 同时检查大图与缩略图

市场作品首先以缩略图被看到。最终配色至少检查：

- 主体是否从背景中分离；
- 暗部是否仍有细节；
- 高光是否吞掉丝状结构；
- 缩略图是否仍能辨认主题；
- 水印或 UI 覆盖是否妨碍判断；
- 放大后是否出现色带断层或过度噪声。

调色助手的输出应包含联系表（contact sheet）、palette 参数和一句差异说明，而不只是若干无名 PNG。

## 6. 功能三：微调与构图

### 6.1 参数的职责

- `centerRe/centerIm`：改变取景，不应大到丢失主体；
- `scale`：控制主体大小、重复密度和呼吸空间，适合几何级数变化；
- rotation：在位置与尺度稳定后再调，避免旋转掩盖取景问题；
- aspect ratio：会改变最终裁切，搜索预览与成品画幅都必须检查；
- iterations / precision：保证细节可信，不是构图工具。

微调通常从基准配方出发，平移量使用视野宽高的一小部分，scale 采用相邻的几何比例。每个候选都记录相对基准的 delta，确保用户选中后能准确还原。

### 6.2 构图检查项

- 主视觉是否明确，第一眼能否找到；
- 重要分支、星角或旋臂是否被裁掉；
- 重复结构的数量和疏密是否服务主题；
- 是否有过大的空白 bulb 或无意义的噪声区；
- 主体居中、偏心或对角线布局是否有意图；
- 在最终市场卡片比例下是否仍成立；
- “放大”和“移动”是否被分别展示和解释。

寻找 motif 时可以用方形预览提高比较效率，但发布前必须按目标输出比例重新检查。构图助手应输出基准图与变体矩阵，而不是把用户带到一个无法回退的新状态。

### 6.3 把用户反馈转成下一轮硬约束

“不像”“还是连起来了”“配色不对”不能只作为闲聊记录。下一轮应将其改写为机器可检查的约束，例如：

- 主体必须是四向结构，并围绕可辨认的小 Mandelbrot；
- 星形应在画面中出现多次，且视觉上彼此分离；
- 背景以红色为主，主体以黄色为主；
- 只接受 Mandelbrot 中的内嵌 Julia，不接受直接 Julia 替代；
- 只改 palette，不改当前坐标与构图。

## 7. 功能四：自动写文案与上架

### 7.1 先验收作品，再写故事

标题、说明和标签必须来自最终配方与最终图像，不能反过来用文案包装未达标候选。五重对称的花瓣可以描述为“五重放射”或“五瓣结构”，不能因为目标曾是五角星就直接写成“五角星”。数学属性也应只写系统实际验证过的内容。

文案可以包含：

- 作品使用的公式或变体；
- 特殊点、周期或 transition 的可靠信息；
- 视觉主体、配色与氛围；
- 适合的展示场景；
- 诚实且克制的创作过程说明。

避免虚构数学结论、夸大稀有性，以及暴露账号密码、API key、服务地址中的秘密参数或内部调试信息。

### 7.2 默认创建草稿

自动化顺序应为：

1. 确认 creator 身份和创建/上架权限；
2. 确认 canonical recipe 已冻结；
3. 确认高分辨率 asset 及其 derivative 可访问；
4. 生成标题、说明、标签、价格和许可建议；
5. 创建私有作品或 listing 草稿；
6. 展示最终预览与元数据供用户确认；
7. 获得发布授权后改变发布状态；
8. 回查市场卡片、详情页、作者、价格、预览与购买状态。

即使用户授权 agent 批量发布，也应为每个作品执行自动 QA，并保留可撤回、可追踪的操作记录。重试必须依赖幂等键或查询已有对象，不能重复生成商品。

## 8. 候选记录格式

建议每次探索都维护结构化 ledger。它既供 agent 延续上下文，也供用户追溯为什么保留或淘汰某张图。

```json
{
  "candidateId": "run-20260730-07",
  "intent": "在 Mandelbrot 内嵌 Julia 中寻找多个视觉上分离的五角星",
  "constraints": {
    "formula": "mandelbrot",
    "embeddedJulia": true,
    "separateMotifs": true,
    "targetAspectRatio": "1:1"
  },
  "canonicalSpec": {
    "centerReStr": "...",
    "centerImStr": "...",
    "scale": "...",
    "iterations": 4096,
    "colorMode": "eq_full",
    "colorMap": "inferno"
  },
  "source": "periodic-point search + logarithmic scale sweep",
  "observation": "五重放射明显，但轮廓为相连花瓣，不满足分离五角星",
  "decision": "rejected",
  "reason": "shape_mismatch",
  "assetStatus": "private",
  "listingStatus": "none"
}
```

实际 spec 应保存所有影响结果的字段，不要把上例当作完整 schema。账号凭证和服务密钥不属于 ledger。

## 9. 已验证的失败模式

### 9.1 对称性不是具象轮廓

本轮探索中，周期点与 multiplier 角度成功找到五重结构，但多次得到五瓣花、五向射线或相连的链状结构，而不是多个分离的五角星。结论是：周期和内部角是强搜索线索，不是视觉形状证明。

### 9.2 数学不连通不等于肉眼分离

一些 Julia 集从拓扑意义上可以是不连通的，但在当前分辨率、尺度和配色下仍表现为连续的 Z 形链或密集细丝。验收约束若是“看起来分开”，就必须按最终图像判断。

### 9.3 直接 Julia 不能替代 Mandelbrot 内嵌 Julia

两者可以共享局部动力学特征，但外部结构和构图语境不同。用户指定内嵌 Julia 时，直接 Julia 最多作为侦察工具，不能作为交付结果。

### 9.4 错误尺度会隐藏正确区域

只盯着 component 尺度容易错过完整 satellite 环或内嵌结构；拉得过远又会淹没目标。深层探索必须进行跨数量级的尺度比较。

### 9.5 配色不能补救错误几何

不正确的结构即使经过强烈红黄配色，也不会自动变成“五角星”或“卍形”。反复调色前应先通过灰度结构验收。

### 9.6 过早发布会污染市场

候选名称一旦暗示了未实现的视觉目标，市场就会出现“标题正确、图像错误”的商品。探索阶段保持私有，只有图像、文案和配方同时通过检查后才发布。

### 9.7 同时改太多参数会丢失因果

坐标、scale、palette、metric 一起变化虽然可能偶然产生好图，却很难知道如何继续微调，也难以建立可复用经验。候选矩阵应明确每一轴在改变什么。

## 10. 质量门与职责边界

发布前至少检查以下七项：

| 检查项 | 通过条件 |
|---|---|
| 数学正确性 | 公式、坐标、特殊点/周期描述可验证。 |
| 视觉约束 | 主体形状、数量、连通性符合用户明确要求。 |
| 色彩可读性 | 大图和缩略图都有层次，无明显灰泥、过曝或色带故障。 |
| 构图 | 主体明确、裁切合理、画幅适配市场展示。 |
| 可复现性 | exact coordinates、scale、渲染与染色参数完整保存。 |
| 元数据诚实性 | 标题和文案没有把“相似”写成“已经实现”。 |
| 发布状态 | creator、asset、listing、权限、价格和公开状态均正确。 |

agent 可以自动淘汰技术失败和明显不符合硬约束的候选；主观审美相近的候选应交给用户选择。agent 不应自行修改数据库会员资格、绕过权限或使用明文凭证；需要测试身份时，应通过项目既有的管理与密钥机制。

## 11. 后续 agent 的最小能力接口

本文不规定实现技术，但四项功能的输出边界应尽量稳定：

1. **Location Finder**：输入视觉意图和当前视野，输出带理由、精确坐标和预览的排序候选。
2. **Color Assistant**：输入冻结的结构 spec，输出 4–8 个带参数与差异说明的配色变体。
3. **Composition Refiner**：输入基准 spec，输出带 center/scale/rotation delta 的构图矩阵。
4. **Listing Assistant**：输入已验收的作品与 creator 上下文，输出诚实文案、listing 草稿和发布前检查结果。

各功能都应读取并追加同一份候选 ledger，避免在阶段切换时丢失精度、用户否决理由或发布状态。

## 12. 衡量辅助探索是否有效

后续评估 agent 时，建议关注：

- 从用户描述到首个“有希望候选”的时间；
- 每轮候选的人工接受率；
- 从预览到最终发布的比例；
- 用户对位置、配色、构图和文案分别修改了多少；
- 同一 canonical spec 能否稳定复现；
- 因形状误判、文案失真或重复上架产生的返工次数；
- 已发布后需要撤回或修正的比例。

核心目标不是让 agent 生成更多图片，而是用更少的无效渲染，更快找到符合意图、可复现、可诚实描述并值得发布的作品。
